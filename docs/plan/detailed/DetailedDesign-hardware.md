## 1. 昇降部

**旧版 [§1](../archive/v1/detailed/DetailedDesign-hardware.md) のピン・決まりごとを使う**（MD10C DIR=GPIO27・PWM=GPIO14、下端=GPIO32（NC 配線））。**ただしこの 3 本は旧版から付け替えた**（2026-10-16 ユーザー指示。旧版は DIR=GPIO14・PWM=GPIO32・下端=GPIO27）。
**HC-SR04 は外し**（spec 2026-10-15）、空いた GPIO25・26 にエンコーダをつなぐ（§1.1）。

### 1.1 高さのエンコーダ（E6A2-CW3C。`WP-LIFT-05`）

| 項目 | 決まり | 理由・出典 |
| --- | --- | --- |
| 付ける所 | 巻き取りドラムの**大ギア（m1.5・z86）にかみ合うピニオン（z16）の軸**。ドラム 1 周でエンコーダ 86/16 = 5.375 周。ギアでつなぎ、ベルト等の滑る伝達を挟まない | spec [Spec-safety.md](../spec/Spec-safety.md) §1.2。滑りはそのまま高さのずれになる。機構の設計値（2026-10-25）。上げ下げを替えたときはギアのバックラッシ分だけ数が遅れる（下端に着くたびに消える） |
| 電源 | **5 V**（ESP32 の基板の 5 V）・GND は ESP32 と共通 | OMRON カタログ: DC 5〜12 V（−5 %〜＋10 %）・20 mA 以下 |
| A 相 / B 相 | **GPIO25 / GPIO26**（**仮**。旧 HC-SR04 の TRIG・ECHO の跡） | ストラッピングの 0・2・5・12・15 を避ける |
| プルアップ | **3.3 V へ 2.2 kΩ**（**仮**）を A・B それぞれに付ける。**5 V へプルアップしない** | オープンコレクタなので、プルアップ先が入力の電圧になる。ESP32 は 5 V に耐えない。内蔵プルアップ（約 45 kΩ）だけでは立ち上がりが遅い |
| 分解能 | **360 P/R**（4 逓倍で 1 周 1440 カウント） | 2026-10-25 に確定 |
| 高さへの換算 | **エンコーダ 1 周で昇降機が約 37.5 mm 上がる**（機構の設計値）。1 カウント ≈ 26.0 µm（37.5 mm ÷ 1440）→ `LIFT_UM_PER_COUNT` = 26（整数に丸めたずれ 0.16 %） | 機構の設計値（2026-10-25 確定）。**ロープ径 4 mm を含む**: π × (Φ60.13 ＋ 4) ÷ 5.375 ≈ 37.48 mm。ロープは 2 本で昇降機を引き、昇降比 2 は 2 本を合わせた巻き取り量に対する比（1 本あたりの巻き取り量＝上昇量）。**巻き太り（2 層目以降）の分は入っていない**ので `WP-MEAS-01` で全行程を測って直す（spec `H-V12`）。**2026-10-27 の実機**: 300 mm までは巻尺との差 ＋2 mm、300 mm を過ぎるとロープが 2 層目に乗り（ドラムは 2 層目を許容する設計）、500 mm で表示が −13 mm（300→500 の間は約 7.5 % 多く上がる）。下げて合わせるとたるみでさらに −16 mm |
| 数え方 | **ESP32 のパルスカウンタ（PCNT）で A/B の 4 逓倍**。`loop` で読むのは差分だけ | `loop` のポーリングや割り込みで数えると、WiFi・WS の処理で `loop` が詰まったときにパルスを落とす |
| Z 相（原点） | **無い型**。原点は下端スイッチで取る（[DetailedDesign.md](DetailedDesign.md) §4.1.1） | CW3C は A/B のみ（Z 付きは CWZ3C） |

出典: OMRON E6A2-C カタログ <https://www.fa.omron.co.jp/data_pdf/cat/e6a2-c_ds_j_8_4.pdf>（2026-10-15 に確認）。

### 1.2 組み立て用のスイッチ（`env:esp32dev_manual`。台帳 `W-2`）

メカの組み立て用に、本番と同じ ESP32・MD10C のまま、ファームだけ書き替えてスイッチで回す。**安全装置は効かない**（`W-2`）。

| 項目 | 決まり | 理由 |
| --- | --- | --- |
| スイッチ | <on>-off-<on> のモーメンタリ（倒している間だけ入る） | 手を離せば止まる |
| 上昇側 / 下降側 | **GPIO33 / GPIO13**（**仮**）。共通端子は GND | 使用中（27・14・32・25・26）・ストラッピング（0・2・5・12・15）・フラッシュ（6〜11）・UART（1・3）・内蔵プルアップの無い 34〜39 を避けた |
| 受け方 | `INPUT_PULLUP`。入っている側が LOW。**両方 LOW（配線の誤り）は停止** | 外付けの抵抗が要らない |
| デューティ | **40 % 固定**（`MANUAL_DUTY_PCT`） | ユーザー決定 2026-10-16 |
| 間 | 動き出しはチャタリング除けに 30 ms、止めてから次に動き出すまで 150 ms（反転は必ずこの停止を挟む）。離したらすぐ止める | 逆向きの突入を MD10C とギアにかけない（安全装置ではない） |

### 1.3 点検用の物理ボタン（本番のファーム `env:esp32dev`。2026-10-29）

spec [Spec-ui.md](../spec/Spec-ui.md) §0.3。**§1.2 と同じスイッチ・同じ配線**を本番のファームでも読み、安全の判定を通して動かす（[DetailedDesign.md](DetailedDesign.md) §4.1.3）。

| 項目 | 決まり | 理由 |
| --- | --- | --- |
| スイッチ・ピン・受け方 | §1.2 と同じ（GPIO33 上昇 / GPIO13 下降・`INPUT_PULLUP`・入っている側が LOW）。ピンの定数は `config.h` の **`LIFT_SW_UP_PIN`・`LIFT_SW_DOWN_PIN`**（旧 `MANUAL_SW_UP_PIN`・`MANUAL_SW_DOWN_PIN`。組み立て用ファームも同じ名前を使う） | 配線を替えずに両方のファームで使える |
| 線が切れた | プルアップで HIGH ＝ 離した | 止まる側に倒れる |
| 両方 LOW | 止める | 配線の誤り（スイッチの作りでは同時に入らない） |

### 2.1.1 UnitV2 の実機調査の結果（`WP-MEAS-06`。2026-10-06）

PC から USB の有線（`10.254.239.1`）と SSH で調べた（2026-10-06・07）。**機器に残る変更はしていない**（組み込みのサービスは一度止めて、元どおり起動し直した）。

| 項目 | 結果 | 設計への影響 |
| --- | --- | --- |
| OS・Python | Linux 4.9.84（armv7l）・glibc・BusyBox。**Python 3.8.6** | `DD-7` のとおり |
| 入っている依存 | **`aiohttp` 3.6.2・`pyserial` 3.4・OpenCV 3.4.9・numpy 1.16.4・PyYAML 5.3.1**（`zeroconf`・`tomli` は無い） | **OS のものをそのまま使う**。ホストの `.venv38` も同じ版に揃える（[-names.md](DetailedDesign-names.md) §1） |
| 依存の追加 | `m5stack` の `pip3` は権限エラーで動かない。**純 Python の wheel はアプリの置き場に展開して `PYTHONPATH` で読める**（`tomli` で確認）。UnitV2 からインターネットへは出ない（`th-rpi-ap` の既定経路の先が無い） | 足すのは純 Python のものだけ・開発機で落として展開して持ち込む。**C 拡張の追加は避ける** |

| **自前の AP** | **同時に `hostapd` が AP `M5UV2_4afd` を `wlan1` で出している**（`th-rpi-ap` と同じ 1 ch・20 MHz） | `th-rpi-ap` の帯域を食いうる（spec `H-A8`）。**配備で止める**（`P-11`。2026-10-07 採用） |

### 2.4 Arduino の決まりごと

| 部品 | 決まりごと | 理由 |
| --- | --- | --- |
| 28BYJ-48 | 止めている間はコイルの電流を切る。指令が途絶えたときも同じ | 旧版と同じ（発熱・電池） |
| 28BYJ-48 | 刻みは Timer2 の割り込みで、`IO_STEP_TICK_US` ごとに位相を足す | I2C の読み取りや行の解釈でループが止まっても刻みが揺れない |
| MG996R | 指令が途絶えても**パルスを止めない**（その角度で保つ）。起動時は `PITCH_INITIAL_DEG` へ一気に動く | パルスを止めると脱力してカメラが倒れる。起動時の跳びはサーボの性質 |
| SRF02 | `Wire.setWireTimeout()` で I2C の時間切れを付け、時間切れは `st=1` で送る | I2C が固まって `loop` が止まるのを防ぐ（**使っている Arduino AVR コアがこの関数を持つかを `WP-IO-02` のビルドで確かめる**） |
| 全体 | AVR のウォッチドッグ（`IO_WDT_TIMEOUT`）。`loop` が回るたびに叩く | それでも固まったら再起動する。**再起動するとピッチが `PITCH_INITIAL_DEG` へ跳ぶ**（受け入れる。[-open.md](DetailedDesign-open.md) `P-8`） |

## 3. 電源

| 何を | どこから | 非常停止で | 備考 |
| --- | --- | --- | --- |
| 昇降部 | 旧版と同じ | 切れる（モータ）／未確認（ESP32。旧版 `D-3`） | |
| UnitV2 | モバイルバッテリの**出力 B**（USB Type-C） | 切れない | 5 V・500 mA |
| Arduino UNO | **出力 B**（UnitV2 と同じ側。USB-B または 5 V ピン） | 切れない | **サーボと分ける**（下記） |
| **MG996R・28BYJ-48（ULN2003）** | モバイルバッテリの**出力 A**（モータ専用） | 切れない | 大きめのコンデンサ（数百〜1000 µF）を近くに置く |
| SRF02 | UNO の 5 V | 切れない | 消費は小さい |

**モータの電源を UNO・UnitV2 と分ける**: MG996R は動き出しや拘束で大きな電流を流す。同じ出力だと電圧が落ちて **UNO が再起動し、ピッチが初期角へ跳ぶ**（§2.4）・UnitV2 が落ちる。
**出力が 2 つあり、モータ側の出力が MG996R の拘束電流をまかなえるモバイルバッテリ**を使う（[-open.md](DetailedDesign-open.md) `D-9`）。**GND はすべて共通にする。**
