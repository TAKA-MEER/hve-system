## 2. 全体構成

```
操作端末（ブラウザ）
  │  HTTP  :80    画面・設定 API            ┐
  │  WS    :80/ws 操作（押している間）・状態 ├─ カメラ部ラズパイ  hve_camera（Python）
  │  HTTP  :8080  映像（MJPEG）            ┘                    ustreamer
  ▼                                          ├ ヨー: ステッピング ┐
カメラ部ラズパイ ─────────────────────────────├ ピッチ: サーボ     ├ pigpio
                                             ├ 天井: 超音波      ┘
        WS クライアント  ──(th-rpi-ap)──→  昇降部 ESP32  hve_lift（:80/ws）
                                             ├ MD10C → パワーウィンドウモータ
                                             ├ 下端: リミットスイッチ
                                             └ 高さ: 超音波
```

| 部分 | 何で作るか | 理由 |
| --- | --- | --- |
| 昇降部ファーム | PlatformIO ＋ Arduino（ESP32）。**`espressif32@7.0.1` に固定** | 先行試作と同じ。2026-09-25 にこの版で試作のビルドが通ることを確認した。`ledcSetup` 等の API が版で変わるため固定する |
| 昇降部 ⇔ カメラ部 | WebSocket（ESP32 がサーバ、ラズパイがクライアント）＋ JSON | 先行試作の通信をそのまま使える。仕様は [-protocol.md](DetailedDesign-protocol.md) |
| カメラ部アプリ | Python 3（Raspberry Pi OS 同梱）＋ `aiohttp` ＋ `pigpio` | 画面配信・WS サーバ・WS クライアントを 1 つの依存で賄える。サーボ・ステッピング・超音波のタイミングは `pigpio`（デーモンがハードウェアで刻む） |
| 映像 | `ustreamer`（MJPEG） | 低遅延を目的に作られた配信ソフト。アプリと別プロセスにして、アプリが止まっても映像は残す |
| 画面 | 素の HTML ＋ JavaScript（ビルド無し） | Node の道具を持ち込まない。ラズパイが静的ファイルとして配る |
| 設定の保存 | カメラ部ラズパイの JSON ファイル | spec「機器側に保存」。画面を出す機器なので読み書きが 1 か所で済む |

## 3. 天井の判定を無線越しに守る仕組み（最重要）

spec [Spec-safety.md](../spec/Spec-safety.md) §2 #4「天井の値が読めない・古いときは上昇しない」を、
**2 つ目のタイマーを作らずに**実現する。

1. **天井の許可は、移動指令そのものに載せる**（`ceil_ok`）。天井の状態を別の通知にしない
2. カメラ部は**指令を送るその瞬間に**、最後の天井の読み値と**その経過時間**から `ceil_ok` を計算する。
   **前回の結果を使い回さない**
3. 昇降部は `ceil_ok` が `true` でない限り上昇しない（欠けている・読めない JSON も `false`）
4. 指令が途絶えれば昇降部のウォッチドッグで止まる

→ **「天井の値が古い」と「指令が古い」が同じ事象になる。**カメラ部が落ちても、無線が切れても、
センサが死んでも、上昇は最長で `ceiling_stale_ms` ＋ `LIFT_CMD_TIMEOUT_MS` 以内に止まる。

## 4. 部分ごとの設計

### 4.1 昇降部（`firmware/lift/`）

| 層 | 中身 | ホストで試験 |
| --- | --- | --- |
| `lift_decide()` | 純関数。指令・下端・高さ・経過時間から「方向・デューティ・停止理由」を決める | ○ |
| `LiftController` | 指令の受付・ウォッチドッグ・`lift_decide()` の結果を**モータに効かせる**。ハードウェアは `hal.h` の抽象を通す | ○（偽 HAL） |
| `cmd_codec` | JSON ⇔ 構造体。読めないものは停止指令になる | ○ |
| `hal_esp32` ／ `main.cpp` | 実物の MD10C・スイッチ・超音波・WiFi・WS。**`main.cpp` は組み立てて呼ぶだけ**にする | × |

判定の規則（上から順に、最初に当たったもので止める）:

| # | 条件 | 結果 | 停止理由 |
| --- | --- | --- | --- |
| 1 | 最後の指令から `LIFT_CMD_TIMEOUT_MS` 超 | 停止 | `CMD_TIMEOUT` |
| 2 | 指令が `stop` | 停止 | `CMD_STOP` |
| 3 | 上昇 かつ `ceil_ok != true` | 停止 | `CEILING` |
| 4 | 上昇 かつ 高さが読めない・`HEIGHT_STALE_MS` 超 | 停止 | `HEIGHT_UNKNOWN` |
| 5 | 上昇 かつ 上端の閾値が未設定 | 停止 | `TOP_UNSET`（提案 `P-2`） |
| 6 | 上昇 かつ 高さ ≧ 上端の閾値 | 停止 | `TOP` |
| 7 | 下降 かつ 下端スイッチが押されている | 停止 | `BOTTOM` |
| 8 | 同じ方向へ `LIFT_MAX_RUN_MS` 超 連続 | 停止 | `MAX_RUN`（提案 `P-1`） |
| 9 | それ以外 | 指令どおり。デューティは `0`〜`LIFT_DUTY_ABS_MAX_PCT` に丸める | `NONE` |

### 4.2 カメラ部（`camera/`）

| 層 | 中身 | ホストで試験 |
| --- | --- | --- |
| `ceiling.py` | `ceiling_permission(読み値, 今, 閾値, 古さ)` → `(ok, 理由)` | ○ |
| `settings.py` | 設定の検証（下限 ≦ 初期値 ≦ 上限・絶対範囲）と原子的な保存 | ○ |
| `axes.py` | ピッチ・ヨーの目標角を deg/s で積分し、可動範囲で止める | ○ |
| `control.py` | 操作（押している間）の鮮度判定・どの軸を動かすか・**昇降部への指令を 100 ms ごとに組み立てて送る**・状態の集約 | ○（偽 HAL・偽昇降部） |
| `lift_link.py` | 昇降部への WS クライアント。切れたら再接続し、その間は `LINK_LOST` | ○（偽 ESP32 サーバ） |
| `app.py` | 画面・設定 API・ブラウザとの WS | ○（aiohttp の試験クライアント） |
| `hw/pigpio_hw.py` | 実物のサーボ・ステッピング・超音波 | × |
| `hw/fake_hw.py` ／ `hw/fake_lift.py` | **偽物のモード**（`--fake`）。機器ゼロで画面と判定を動かす | — |

**偽物のモード**（th-system の開発モードに当たる）: `python3 -m hve_camera --fake` で、
センサ値を画面・API から変えられる偽のハードウェアと、偽の昇降部で起動する。
**実装エージェントも管理担当も、機器なしで画面と判定の経路を確かめられる。**
偽物のモードで通した結果を、実機の結果と取り違えないこと（画面に常時「偽物のモード」と出す）。

**依存の入れ方（インターネット無し）**: カメラ部のラズパイは**配備前にインターネットのある無線で準備する**のが最も簡単
（th-system のラズパイと違い、`th-rpi-ap` に繋ぐ前に他の網へ繋げられる）。できないときは th-system
`docs/network.md`「ラズパイ: pi_serial_relay の導入」と同じく、開発機で wheel ／ `.deb` を落として持ち込む。

## 5. 段階と作業パケット

**各段階の終わりに必ず「動くもの」が残る。**一覧・受け入れ条件は [-packets.md](DetailedDesign-packets.md)。

| 段階 | 残るもの | パケット |
| --- | --- | --- |
| 0 土台 | 空の試験が通る骨格。**試作で昇降の実測値** | `WP-BASE-01` ・ `WP-MEAS-01` |
| 1 昇降部 | ESP32 が指令どおり動き、下端・上端・天井許可・途絶で止まる | `WP-LIFT-01` ・ `WP-LIFT-02` |

| 3 画面 | 操作画面と設定画面 | `WP-UI-01` |
| 4 結合・測定 | 実機で盤前の操作が通る。仮値を実測で置き換える | `WP-MEAS-02`〜`05` |
