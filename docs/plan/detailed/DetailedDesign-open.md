## 1. ユーザー判断待ちの提案

詳細設計を書くうえで決める必要があったが、**spec に無い振る舞い**なので確定しなかったもの。
いまの詳細設計は「提案」の列で書いてある。**覆ったら該当箇所を直す。**採否が出たら spec に書き、この表から消す。

| ID | 問い | 提案 | 理由 | 影響する所 |
| --- | --- | --- | --- | --- |
| **`P-5`** | 上部モジュールが繋がっているところへ、**2 つ目の `/ws/module` の接続**が来たら | **新しい方に置き換える**（古い接続を閉じる。古い方が持ち主ならその場で止まる） | 上部モジュールは 1 台だけ（spec `H-M3`）。UnitV2 が再起動して繋ぎ直したとき、古い接続が切れたと分かるまで待たずに済む。拒む方にすると、半端に生き残った古い接続のせいで繋ぎ直せない | [DetailedDesign.md](DetailedDesign.md) §4.1・`WP-LIFT-04` |
| **`P-6`** | 昇降部の画面のファイルをどう ESP32 に載せるか | **ファームに埋め込む**（ビルド時に gzip して C の配列に） | ファイルシステムの書き込み（`uploadfs`）を別にすると、ファームと画面の版がずれる・書き忘れる | [DetailedDesign.md](DetailedDesign.md) §4.2 |
| **`P-8`** | Arduino が指令の途絶で止めるとき・再起動したときのピッチ | **途絶ではその角度で保つ（パルスを止めない）。再起動したら初期角（正面・水平）へ跳ぶのは受け入れる** | パルスを止めると MG996R が脱力してカメラが倒れる。再起動時の跳びはサーボの性質で避けられない（電源を分けて再起動を起こしにくくする。[-hardware.md](DetailedDesign-hardware.md) §3） | [DetailedDesign.md](DetailedDesign.md) §3.4・[-hardware.md](DetailedDesign-hardware.md) §2.4 |
| **`P-9`** | 持ち主でない操作元が「離した」とき | **無視する**（持ち主の昇降は続く） | 昇降部の画面で押していた人が、上部モジュールに取って代わられたあとで指を離しても、上部モジュールの操作を止めない（最後の操作が勝つ。spec `H-M1`）。止めたい人はもう一度押して持ち主になり、離せば止まる | [DetailedDesign.md](DetailedDesign.md) §3.3 |
| **`P-10`** | カメラモジュールの画面の「繋いでいる端末の数」に、昇降部の画面を数えるか | **別々に出す**（カメラモジュールの画面の数と、昇降部の画面の数） | spec §1.6 の「気づけるようにする」の目的は、操作がぶつかりうる相手に気づくこと。昇降部の画面からも昇降できるので、そちらも見えないと気づけない | [-protocol.md](DetailedDesign-protocol.md) §4・`WP-UI-02` |

（`P-7` は欠番。昇降部の見つけ方は spec `H-M2` で任されたので、提案にせず [DetailedDesign.md](DetailedDesign.md) §4.6 で決めた）

## 2. 詳細設計側の未確定事項

| ID | 問い | 選択肢・状況 |
| --- | --- | --- |
| **`D-1`**（旧版から） | **最初の 1 台をどう開くか**（操作端末が昇降部・カメラモジュールの IP をどう知るか） | 旧版と同じ制約（固定 IP は th-system の網と干渉しうるので勝手に決めない・Android は mDNS を引けない）。v2 では**片方を開ければもう片方へ辿れる**（[DetailedDesign.md](DetailedDesign.md) §4.6）。最初の 1 台は、th-system のラズパイの DHCP の払い出し一覧を見るか、AP 側の DHCP 予約が要る |
| `D-2`（旧版から） | 映像の解像度・フレームレートの上限 | 配信 480p は決定（spec `H-V9`）。fps は `WP-MEAS-06`（UnitV2 の負荷）と `WP-MEAS-03`（無線の圧迫）で決める |
| `D-3`（旧版から） | 昇降部の ESP32 の電源をどこから取るか | 旧版のまま |
| `D-7`（旧版から） | 画面が映像の途絶えを見つけるため `/stream` へ接続を張っては切る負荷 | UnitV2 では CPU に余裕が無いかもしれない。`WP-MEAS-06` で見る |
| **`D-8`** | UnitV2 で確かめること（サービスの止め方・STA・UART の電圧・負荷・依存・自動起動） | [-hardware.md](DetailedDesign-hardware.md) §2.1.1。`WP-MEAS-06` |
| **`D-9`** | モバイルバッテリの型（出力の数・各出力の電流・容量） | [-hardware.md](DetailedDesign-hardware.md) §3。MG996R の拘束電流をモータ側の出力でまかなえること |
