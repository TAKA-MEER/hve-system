# Spec-safety — 上下端と天井

[Spec.md](Spec.md) の詳細。昇降機を**動かしてはいけない所へ動かさない**ための振る舞い。

---

## 1. 検知手段（2026-09-25 ユーザー決定。2026-10-06・2026-10-15 に v2 で見直し）

| 守るもの | 検知手段 | 取り付け |
| --- | --- | --- |
| **下端** | **リミットスイッチ** | 昇降機の下端 |
| **上端**（昇降機の可動範囲の上限） | **昇降の高さ**が上端の閾値に達したら（2026-10-15 ユーザー決定 `H-X9`）。高さは**ロータリエンコーダ E6A2-CW3C** で測る（§1.2） | 昇降部（エンコーダは昇降機を引き上げる**ロープの巻き取り機構**につなぐ） |
| **天井** | **上部モジュールが持つ距離計**（上向き。カメラモジュールは旧版と同じ **SRF02**（I2C）（2026-10-06 ユーザー決定）） | **上部モジュール**に付け、上部モジュールから天井までの距離を測って**昇降部へ送る**（2026-10-06 ユーザー決定。[Spec-module.md](Spec-module.md) §2）。**距離計を持たない上部モジュールからの命令にも、この値を使う**（2026-11-01 ユーザー決定。`H-X11` を改めた）。**設定が入っていれば、単体の操作（昇降部の画面・物理ボタン）にも使う**（2026-11-06 ユーザー決定。§2 #4c） |

### 1.1 上端の検知の一時無効（2026-10-06 ユーザー決定。2026-10-28 にエンコーダで解いた）

上端を検知できる実用的なハードが無かったため一時無効にした（[EXCEPTION-LEDGER.md](../EXCEPTION-LEDGER.md) `W-1`）。
**2026-10-15 にエンコーダで高さを測ることにしたので戻す。**エンコーダで高さを測る実装と実機での確認が済むまでは、無効のまま次のとおり振る舞う。

**2026-10-28 ユーザー決定: エンコーダの高さで上端を検知する（一時無効を解く）。**エンコーダの実装と実機での確認（原点・下端スイッチの誤り・`ENCODER_STALL`）が済んだため。上端の閾値は全行程の確認で機械の上端に当たった高さ（表示 1891 mm）より手前の **1800 mm**（仮。全行程の実測で見直す）。下の表は解く前の振る舞いの記録。

**高さの表示は、下端（原点）から上がった量で、床からの高さではない。**床からは、下端のとき**機体が約 1900 mm、腕の支点（昇降機の上端）が約 1700 mm**で、そこから上端の閾値 1800 mm まで上げられる（2026-11-04 ユーザー）。そこまで上げる必要が無ければ、安定性のため上端を下げる予定（`H-V3`）。

| 項目 | 無効の間の振る舞い |
| --- | --- |
| §2 #2（上端で止める）・#2a（上端が未設定） | **判定しない**（上端で止まらない） |
| §2 #4 のうち**高さ**が読めない・古い | **上昇を止めない**（高さは上端の検知にしか使わないため） |
| 高さ | **測って画面に出し、上部モジュールへ配信する。判定には使わない** |
| 画面 | 「**上端の検知: 一時無効**」を**常に**出す（#2a と同じ扱い） |

**無効の間に残る守り**: 下端のリミットスイッチ（#1）・距離計を持つ上部モジュールからの操作での天井（#3〜#4）・
連続駆動の上限（#4b）・操作者の目。
**受け入れているリスク**: 昇降部の画面から上昇させると、天井も上端も見ない。**自動で止める仕組みは連続駆動の上限（#4b）だけ**になる。

### 1.2 高さの測り方（2026-10-15 ユーザー決定）

| 項目 | 振る舞い |
| --- | --- |
| 測るもの | ロープの巻き取り機構の回転をエンコーダで数え、昇降の高さに直す（超音波距離計 HC-SR04 は使わない） |
| 原点 | **下端のリミットスイッチが押されたら、高さを 0 にする**（下端に着くたびに取り直す） |
| 原点が決まる前 | **電源投入・再起動のあと、一度下端に着くまでは高さを「読めない」とする**（§2 #4。**上昇しない。まず下げて下端に着ける**）。ウォームギアで途中の高さに止まったまま再起動しうるため。**アームの制御器から測定機構の腕が格納位置にないと知らされているときは画面に警告を出すが、下降は拒否しない**（2026-11-02 ユーザー決定）。**腕が出ていたと覚えていて、アームの制御器と通信できないときは、下降も止める**（§2 #4e。2026-11-14 ユーザー決定。[Spec-module.md](Spec-module.md) §5） |
| スイッチの誤り（2026-10-28 ユーザー決定） | **ノイズなどで一瞬だけ押されたように読めたのは、押されたとみなさない**（押された状態が続いてから原点にする）。**原点が決まったあと、下端から離れた高さで押されたと読めたら、原点にせず高さを「読めない」とする**（§2 #4。上昇しない・下降はできる・画面に理由を出す。下端に着けば戻る）。2026-10-28 の実機で、上端付近を上昇中に下端スイッチが一瞬押されたと読め、高さが 0 に戻ったため |

**受け入れているリスク**: エンコーダが数えるのは**巻き取り機構の回転**で、昇降機そのものの位置ではない。
下降中に昇降機が引っかかるとロープだけが繰り出され、**高さの表示は下がるのに昇降機は上に残る**（引っかかりが外れると、その分だけ落ちる）。
ロープの巻き太り・滑りでも高さがずれる。ずれは下端に着くたびに消えるが、**実際の位置との食い違いを検知する手段は無い**。
その場合の最後の砦は連続駆動の上限（#4b）と操作者の目。
測定機構のドラムは昇降機と一緒に上下し、昇降部は動かさないので（2026-11-14。[Spec-module.md](Spec-module.md) §5）、高さの表示がずれても腕を起こす線には効かない。**引っかかりが外れて昇降機が落ちるとき、腕が出ていたらどう扱うかは未定**（`H-X13`）。
**原点を取る前に腕が出ていても、アームの制御器と通信できていれば、下降は拒まない**（2026-11-02 ユーザー決定。通信できないときは #4e で止める。2026-11-14）。測定中に電源が切れると腕は起きたまま残り（ドラムがその場で保つ）、昇降機は原点を取るまで上げられないので、そのまま下げると腕が天面に降りる。fk-system は腕を格納してから下げる（fk-system の決定）。人が下げるときは、警告（[Spec-ui.md](Spec-ui.md) §1.6）を見て人が守る。
**fk-system・ss-system からの自動の操作では操作者の目が無い**（2026-11-01 に fk-system へ伝えた）。天面への押し当てに昇降機の下降を使わないのは fk-system の方針（fk-system `FK-A5`）。

## 2. 振る舞い

| # | 状況 | 振る舞い |
| --- | --- | --- |
| 1 | 下端のリミットスイッチが押されている | **下降しない。**上昇はできる |
| 2 | 昇降の高さが上端の閾値に達した | **上昇しない。**下降はできる |
| 3 | （**上部モジュールからの操作のとき**、および**単体の操作で #4c の設定が入っていて距離計を持つ上部モジュールと通信できているとき**（2026-11-06）。距離計を持たない上部モジュールからの操作でも、距離計を持つ上部モジュールの値で判定する（2026-11-01）。#3a・#3b・#4 の天井の部分も同じ）上部モジュールから天井までの距離が閾値**以下**になった（ちょうど閾値でも止める。**閾値は設定で変えられる**。[Spec-ui.md](Spec-ui.md) §2.3。2026-11-06） | **上昇しない。**下降はできる |
| 3a | 天井の距離計が**近すぎて測れない**（最小測定距離より近い。SRF02 で約 15 cm） | 「天井が近い」とみなし、**上昇しない。**下降はできる |
| 3b | 天井の距離計に**反射が返らない**（測定範囲より遠い。SRF02 で約 6 m） | 「天井は遠い」とみなし、**上昇を許す。**画面に「天井: 範囲外」と出す |
| 4 | 高さ・天井の距離が**読めない・古い**（高さの原点が決まる前（§1.2）、センサの故障、上部モジュールとの通信断、上部モジュールの電池切れ、**距離計を持つ上部モジュールが繋がっていない**（上部モジュールからの操作のとき。2026-11-01））。**天井の通信断・古い・繋がっていないで止めるのは上部モジュールからの操作だけ。単体の操作では止めずに天井を使わない（#4c。2026-11-06）** | **上昇しない。**下降はできる。画面に理由を出す（高さの部分は一時無効。§1.1） |
| 4d | **モータへ出力しているのにエンコーダが回らない**状態が続いた（ロープが外れた・エンコーダの故障・引っかかり。2026-10-15 ユーザー決定） | **止める。**反対方向へは動かせる。画面に理由（エンコーダが回らない）を出す。速度の制御が出力を上げ続けるのを防ぐ。**出力そのものはモータへの出力の上限（[Spec-ui.md](Spec-ui.md) §2.1）より上げない** |
| 4c | **昇降部の画面からの操作**（単体での操作）、または**昇降部の物理ボタン（点検用）からの操作**（2026-10-29。[Spec-ui.md](Spec-ui.md) §0.3）。2026-11-01 に「距離計を持たない上部モジュールからの操作」（`H-X11`）を外した | **設定「単体の操作でも天井で止める」（[Spec-ui.md](Spec-ui.md) §2。既定は入）が入っていて、距離計を持つ上部モジュールと通信できているときは、その天井の距離を使う**（#3・#3a・#3b。**距離計が読めないと知らせてきたときは上昇しない**。2026-11-06 ユーザー決定）。**設定が切のとき、または距離計を持つ上部モジュールが繋がっていない・通信が途切れた・値が古いときは、天井の距離を使わず、上昇を許す。人が見て守る**。画面に、天井を使っているか、使っていないならその理由（設定が切・通信なし）を出す。下端・上端・#4 の高さ・#4b・#4d は効く（[Spec-module.md](Spec-module.md) §2） |
| 2a | **上端の閾値がまだ設定されていない** | **開発中の動作確認とみなし、上昇を許す。**画面に「上端が未設定（開発中）」と**常に**出す |
| 4b | **同じ方向へ動き続けた時間が上限を超えた**（上限は、**上端の閾値までの全行程を、そのときの目標の速さで進む時間の約 1.5 倍**。目標の速さから都度求める。2026-10-29 ユーザー決定） | **止める。**反対方向へは動かせる |
| 4e | **測定機構の腕が格納位置にない（または腕の状態が分からない）と最後に知った状態で、アームの制御器と通信できなくなった**（2026-11-14 ユーザー決定。2026-11-01 の「測定機構を検知しているのに通信できない」を、コネクタが無くなったので改めた。通信できないとみなす時間は `H-M7`。[Spec-module.md](Spec-module.md) §5）。**最後に知った腕の状態は電源を入れ直しても覚えておくので、電源を入れ直したあと、通信できるまでのあいだも含む**（2026-11-14 ユーザー決定。`H-X15`） | **上昇も下降もしない。**どこからの操作でも同じ（昇降部の画面・**点検用の物理ボタン**を含む）。画面に理由を出し、昇降部の画面に確認ダイアログを出す。**通信が戻るか、昇降部の画面で人が「測定機構を取り外した、または腕の安全を確かめた」と答えれば動かせる。**最後に格納位置にあると知っていたとき、覚えている腕の状態が無いとき（アームの制御器と通信できたことが無い）は止めない。原点を取る前の下降も、この止め方が先に効く |
| 5 | 1〜4e で止めたとき | 操作者に**なぜ止まったか**を画面で示す |

**「古い」とみなす時間は仮に 600 ms と置き、実測で確定する**（`H-V8`。600 ms は先行試作と th-system のウォッチドッグの値に揃えた仮値で、根拠は無い）。

**2a は 2026-09-28 ユーザー決定**（`P-2`）。上端の閾値は実測（全行程の測定）で決めて書き込む。
**未設定の間は上端で止まる仕組みが無い**ので、下端スイッチ・天井の距離計・連続駆動の上限（4b）と操作者の目で守る。

**4b は 2026-09-28 ユーザー決定**（`P-1`）。高さが**もっともらしい誤った値**になる場合（ロープの滑り・引っかかり・巻き太り。§1.2）の最後の砦。

**2026-10-29 ユーザー決定で、上限を固定の 10 秒（仮）から、目標の速さから都度求める値に替えた。**10 秒では既定の 30 mm/s で 300 mm しか進めず、全行程を一度で動かせなかったため。

| 項目 | 振る舞い |
| --- | --- |
| 上限の時間 | 上端の閾値（#2）を目標の速さで進む時間の約 1.5 倍（1800 mm なら 30 mm/s で約 90 秒・100 mm/s で約 27 秒）。**上端の閾値が未設定（#2a）のときは、機械の全行程（仮 1900 mm。2026-10-28 に機械の上端に当たった表示 1891 mm）で求める** |
| 途中で目標の速さを変えた | **それまでの目標の速さで進んだとみなした距離**で数える（速さを上げた途端に止まらない） |
| 数え直すとき | 今までどおり。止めた・向きを替えたら数え直す。操作する人が替わっても数え直さない |
| 測った速さは使わない | 上限はエンコーダ（§1.2）に頼らない守りなので、目標の速さだけから求める |

**受け入れているリスク**:
- モータへの出力の上限（[Spec-ui.md](Spec-ui.md) §2.1）に当たって目標の速さに届かないと、全行程の手前で止まることがある（押し直せば続けて動く）。
- 目標の速さが遅いほど上限は長い（10 mm/s で約 4.5 分）。下端スイッチが位置ずれなどで押されないまま下降を続けると、ロープが繰り出されてエンコーダは回るので #4d も効かず、この上限まで止まらない。そのあいだは人が見て守る。

**高さを直近 5 回の読み値の中央値にする扱い（2026-10-01 ユーザー決定）は、2026-10-15 にやめた。**
超音波距離計に WiFi のノイズが乗る前提の決まりで、エンコーダの高さには当たらない。

**3b は 2026-09-28 ユーザー決定**（`H-X8`）。許さないと天井の高い場所で一切上昇できないため。
**受け入れているリスク**: 距離計が壊れて反射を拾えなくなった場合と区別できず、そのときは天井があっても上昇できてしまう。
距離計との通信そのものが途絶えた場合は 3b ではなく #4（上昇しない）になる。

**#4 は必須。**天井の距離は上部モジュールで測り、昇降機を動かすのは昇降部なので、
**無線を挟んだ判定になる**。値が届かないことを「近くない」と扱うと、通信が切れた瞬間に天井へ突っ込む。

**#4c は 2026-10-06 ユーザー決定**（`H-X10`）。昇降部は単体で動かせる（[Spec.md](Spec.md) §4 `HD-4`）が、天井の距離は上部モジュールにしか無いため。
**天井を使うかは「上部モジュールがつながっているか」ではなく「命令がどこから来たか」で決める**（上部モジュールからなら使う）
（[Spec-module.md](Spec-module.md) §2。上部モジュールの判断ではなく昇降部が決める。`H-M4`）。
2026-11-01 ユーザー決定で、「上部モジュールが距離計を持つと送ってきたか」で分けるのをやめた（`H-X11`。fk-system・ss-system が距離計を持たずに自動で上げるため）。
こうすると、上部モジュールからの命令で値が途切れたとき・距離計を持つ上部モジュールが居ないときは #4（上昇しない）になり、「もともと無い」と取り違えない。
**2026-11-06 ユーザー決定で、単体の操作（昇降部の画面・物理ボタン）でも、設定が入っていて距離計を持つ上部モジュールと通信できているときは天井で止める**（`H-X10` を改めた。既定は入）。単体で上げるときにも、カメラモジュールが測っている天井を守りに使えるように。
単体の操作に限っては、天井を使うかが「距離計を持つ上部モジュールと通信できているか」でも変わる。**通信できない・値が古いときは #4 にせず、今までどおり天井を使わずに上昇を許す**（カメラモジュールを載せずに単体で動かすことがあるため）。距離計が読めないと知らせてきたとき（通信はできている）は #4 と同じく上昇しない。
**受け入れているリスク**: 単体の操作では、**上昇中に通信が途切れる・値が古くなると、天井を使わずにそのまま上昇を続ける**（上部モジュールからの操作の #4 と逆の扱い。人が見て守る前提の操作なので受け入れる。天井を使っていないことは画面に出す）。設定が切のとき（設定画面は誰でも触れる。[Spec-ui.md](Spec-ui.md) §2）は、上部モジュールが天井の近さを測っていても止まらない。
**受け入れていること**（2026-11-01）: 距離計を持つ上部モジュール（カメラモジュール）が繋がっていないと、ほかの上部モジュール（fk-system・ss-system）からは上昇できない。

**#4e は、2026-11-01 ユーザー決定（fk-system からの申し送り）を 2026-11-14 に改めたもの。**
それまでは、腕を起こすドラムが機体側にあり、昇降機を動かすと線の長さが変わるので、ドラムを合わせられないまま動かすと線が張って腕や線を傷めるか、緩んで腕が落ちる、というのが止める理由だった。
**2026-11-14 fk-system の決定で、ドラムは昇降機の上部へ移ってアームの制御器が動かし、昇降部の基板のコネクタも無くなった**（fk-system [Spec-open.md](../../../../fk-system/docs/plan/spec/Spec-open.md) §1.2）。昇降機を動かしても腕の角度は変わらない。
**残る理由は、腕が出ているのに、それを確かめられないまま昇降機を動かして、腕を天面や天井に当てること。それでも下降まで止める**（2026-11-14 ユーザー決定）。
**下降まで止めるのは #4e だけ**（ほかの止め方は、どれかの向きには動かせる）。
コネクタが無いので、**アームの制御器と通信できたら測定機構が付いているとみなす**。昇降部は「取り外した」と「通信が切れた」を区別できないので、**最後に知った腕の状態で分け、区別は昇降部の画面で人が答える**（[Spec-module.md](Spec-module.md) §5）。
**受け入れているリスク**:
- 通信が直らないと、人が昇降部の画面で答えるまで、昇降機を上げたまま下ろせない（その間も機体は走れる。[Spec.md](Spec.md) §4 `HD-1` の帰結）。アームの制御器との通信は無線なので、**無線の途切れやアームの制御器の電池切れでも #4e になる**。
- 確認で解いたあと、昇降部は腕を見ていない。腕が出たまま下げれば腕が天面に降り、上げれば天井に近づく。**人が腕を見ながら動かす。**「コネクタを抜いたあとは下げるだけ」（2026-11-04）は、上げると線が張るという理由が無くなったので外した。
- 腕が格納位置にあると最後に知ったあとで通信が切れ、そのあいだに人が腕の画面から腕を起こすと、昇降部は知らないまま動かせる（腕の画面の操作は人が責任を負う）。
- **最後に知った腕の状態は、電源を入れ直しても覚えておく**（2026-11-14 ユーザー決定。`H-X15`。fk-system のユーザーの答えを受けた）。覚えていないと、腕が出たまま昇降部だけ電源を入れ直し、アームの制御器も止まっているとき、警告なしで下げられるため。**そのかわり、腕が出たまま電源が切れてアームの制御器と通信できないと、原点取りの下降もできない**（通信が戻るか、昇降部の画面で人が答えるまで）。

**#4f（コネクタの確認待ち。2026-11-01）と #4g（ドラムが腕の角度を保てない。2026-11-02）は、2026-11-14 に無くした**（番号は詰めない）。
**#4e の形は hve の見解として fk-system に返し、fk-system のユーザーが承認した**（2026-11-14）。

## 4. 非常停止（2026-09-25 ユーザー決定）

| 手段 | 昇降機 | カメラモジュール（ヨー・ピッチ） |
| --- | --- | --- |
| th-system の**物理非常停止ボタン** | **止まる**（電源系統を共有しているので電源が切れる） | 止まらない（リチウムイオンのモバイルバッテリ給電。2026-10-06 ユーザー決定）。**問題なし**（`H-X7`。旧版 2026-09-25・v2 で 2026-10-06 に再確認） |
| th-system の画面の非常停止 | 止まらない（信号のやり取りをしないため。[Spec.md](Spec.md) §4 `HD-1`） | 止まらない |
| 本システムの画面 | 操作を離せば止まる（押している間だけ動く） | 同左 |

**カメラモジュールへの指令が途絶えたら、ヨーは止まり、ピッチはその角度で保つ**（ピッチの力を抜くとカメラが倒れるため）。**カメラモジュールの制御基板が再起動したときは、ピッチが初期の向き（正面・水平）へ一気に動く**（サーボの性質。受け入れる。2026-10-06 ユーザー決定 `P-8`）。
**例外: 外し忘れの省電力では、ピッチの力を抜く**（2026-11-10 ユーザー決定。[Spec-power.md](Spec-power.md) §2）。

本システム専用の非常停止ボタンは設けない。
**電源が切れても昇降機はその場で止まる**（ウォームギアで自己保持する。落下しない）。

**測定機構のドラムのモータの電源をどこから取るかは fk-system で未定**（fk-system `FK-X3`）。「昇降機と同じ電源系統にし、物理非常停止で一緒に切れる」（2026-11-01 ユーザー決定）は、理由（片方だけ止まると腕を起こす線が張るか緩む）が無くなったので 2026-11-14 に取り下げた。物理非常停止でドラムが止まるかは、電源の取り方で決まる。
**電源が切れてもドラムはその場で保つ**（fk-system の側で満たす。fk-system [Spec-arm.md](../../../../fk-system/docs/plan/spec/Spec-arm.md)）。
**アームの制御器は電池で、fk-system の非常停止を無線で受ける**（2026-11-02 fk-system の決定。fk-system `FK-X3`）。th-system の物理非常停止では止まらない（カメラモジュールと同じ）。
