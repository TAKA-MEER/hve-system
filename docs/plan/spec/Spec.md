## 1. 対象

配電盤上部を確認するロボットのうち、**カメラを盤上部へ持っていき、向け、映すまで**のすべて。
本システムは th-system の走行部に載って運ばれるが、**th-system とは独立したシステム**である（§4 `HD-1`）。

| 担当 | 範囲 |
| --- | --- |
| **本システム** | 昇降機による**高さ**、カメラの**ヨー・ピッチ**、映像の表示、それらの操作画面 |
| th-system | 保管場所⇔試験場の移動、盤前への移動・停止、盤前での位置の微調整、機体の非常停止 |

th-system 側でも、カメラ昇降のピッチ・ヨー・高さは範囲外（別担当）とされている
（th-system [Spec.md](../../../../th-system/docs/plan/spec/Spec.md) §1・[Spec-onsite.md](../../../../th-system/docs/plan/spec/Spec-onsite.md) §7.1）。

**撮影した画像の保存・一覧までを含むかは未定**（[Spec-open.md](Spec-open.md) `H-S2`）。

## 2. 用語

th-system [Spec.md](../../../../th-system/docs/plan/spec/Spec.md) §2 の用語（機体・試験員・試験場・盤 など）をそのまま使う。
ここには本システムで新たに要る語だけを足す。

| 用語 | 意味 |
| --- | --- |
| 昇降機 | 機体に載り、上部モジュールを上下させる機構 |
| 昇降部 | 昇降機とそれを動かす電子回路。**単体で動かせる**（§4 `HD-4`） |
| 上部モジュール | 昇降機の上端に載せる、**交換できる**機器（ソフトウェアごと）。昇降部に昇降を命じ、昇降部の状態を受け取れる |
| カメラモジュール | 上部モジュールのうち、カメラを載せてヨー・ピッチを動かせるもの。**いま作るのはこれだけ** |
| 操作者 | 本システムを操作する人。th-system の試験員と同じ人かは問わない |
| 移動システム | th-system のこと |

## 4. 設計思想

記号は `HD-n`（th-system の `SD-n` と区別する）。

* **HD-1 th-system から独立させる。**互いの仕様変更が波及しないようにする。**th-system とは通信しない**
  （どうしても要るときも最低限にし、先にここを更新する）。走行禁止などの**連動も設けない**。
  共有するのは機体（載せてもらう）と無線 AP だけ
* **HD-2 操作画面は th-system と別に持つ**
* **HD-3 高さは人が映像を見て決める。**盤ごとの高さを事前に登録・計測する仕組みを前提にしない（§6）
* **HD-4 上部はソフトウェアごと交換できるモジュールにする。昇降部は単体で動かせる。**（2026-10-06 ユーザー決定）
  昇降部は自分の操作画面を持ち、上部モジュールが無くても昇降できる。
  上部モジュールは昇降部に**昇降を命じ**、昇降部から**状態（センサの値など）を受け取る**。
  **昇降部と上部モジュールの間の取り決めは [Spec-module.md](Spec-module.md)。**
  カメラモジュールを別の機能の機器に替えても、昇降部は作り直さない

**HD-1 の帰結として受け入れていること:**

| 帰結 | 扱い |
| --- | --- |
| th-system の**画面の**非常停止では昇降機は止まらない | 受け入れる。**物理非常停止ボタンは電源系統を共有しているので昇降機も止まる**（信号のやり取りではなく電源の共有。[Spec-safety.md](Spec-safety.md) §4） |
| 昇降機が上がったまま機体が走れる | 既知のリスクとして残す（[archive/v1/spec/Spec-open.md](../archive/v1/spec/Spec-open.md) §1） |
| AP を共有するので、映像が th-system の無線を圧迫しうる | 「干渉しない」を守るため映像の上限を決めて確かめる（`H-A8`） |

## 5. 全体構成

| 構成要素 | 中身 | 役割 |
| --- | --- | --- |
| **昇降部** | **旧版と同じ**（2026-10-06 ユーザー決定）: ESP32 ＋ モータドライバ Cytron MD10C ＋ 昇降機のモータ（**パワーウィンドウモータ**） ＋ **下端リミットスイッチ** ＋ **上向き超音波距離計 HC-SR04**（昇降の高さ）。**上端の検知手段は検討中**（`H-X9`。HC-SR04 の信頼性を検証中） | 上部モジュールを上下させる。**自分の操作画面を出す** |
| **カメラモジュール**（上部モジュール） | カメラ **M5Stack UnitV2** ＋ **Arduino**（機種未定・`H-A10`。UnitV2 と **UART** でつなぐ） ＋ ヨー用ステッピングモータ **28BYJ-48**（旧版から続投） ＋ ピッチ用サーボ **MG996R** ＋ **天井までの距離計**（機種未定・`H-A10`） ＋ 電源は**リチウムイオンのモバイルバッテリ**（2026-10-06 ユーザー決定） | 映像を送り、向きを変え、天井までの距離を測る。**カメラモジュールの操作画面を出す** |
| 無線 | `th-rpi-ap`（th-system のラズパイが出す AP。**将来名前が変わる**） | 操作端末・昇降部・上部モジュールをつなぐ |
| 操作端末 | 未定（`H-A9`） | 昇降部・カメラモジュールの操作画面を開く |

**Arduino がヨー・ピッチのモータを動かし、UnitV2 が Arduino に指令を送る**（2026-10-06 ユーザー決定）。
**操作画面は 2 つある**: 昇降部の画面（昇降だけ）と、カメラモジュールの画面（映像・昇降・ヨー・ピッチ。旧版と同じ）。[Spec-ui.md](Spec-ui.md) §0。
**昇降部のモータは th-system の駆動系と同じ電源系統**で、th-system の物理非常停止ボタンで一緒に電源が切れる。
AP の名前は将来変わるので、**名前を変えても設定の書き換えだけで済むようにする**。

## 6. 操作の流れ（盤前）

1. th-system が盤前に機体を止める（本システムは関与しない）
2. 操作者がカメラモジュールの画面を開き、**カメラ映像を見ながら昇降機を上昇させる**（速度はスライダーで変える。[Spec-ui.md](Spec-ui.md)）。上端・天井に近づいたら上昇は止まる（[Spec-safety.md](Spec-safety.md)）
3. **操作者がよいと思ったところで止める**
4. 必要ならヨー・ピッチで向きを合わせ、デジタルズームで拡大して盤上部を確認する（[Spec-ui.md](Spec-ui.md) §1.5）
5. 下降させてから、th-system 側で次の盤へ移動する

昇降部の画面は、上部モジュールが無くても昇降機を動かせるようにするためのもの（`HD-4`）。

操作を補う工夫（映像の遅延を踏まえた速度の切替・ガイド表示など）の案は
[operation-ideas.md](../operation-ideas.md)（検討メモ。spec ではない）。
