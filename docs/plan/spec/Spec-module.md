# Spec-module — 昇降部と上部モジュールの取り決め

[Spec.md](Spec.md) §4 `HD-4` の詳細。**上部モジュールを替えても昇降部を作り直さない**ための、両者の間の約束。
通信の手段・形式・周期は書かない（詳細設計の役割）。

---

## 1. 方針（2026-10-06 ユーザー決定）

| 項目 | 振る舞い |
| --- | --- |
| 昇降部 | **単体で動かせる。**自分の操作画面を持ち、上部モジュールが無くても昇降できる。**点検用の物理ボタンも持つ**（[Spec-ui.md](Spec-ui.md) §0.3）。測定機構が付いているときは §5 の決まりが加わる（2026-11-01 ユーザー決定） |
| 上部モジュール | **ソフトウェアごと交換できる。**昇降部に**昇降を命じ**、昇降部から**状態を受け取る**。**カメラモジュールのほか、fk-system・ss-system も上部モジュールとして繋ぐ**（2026-11-01 ユーザー決定。[Spec.md](Spec.md) §1.1） |
| つなぎ方 | 昇降部と上部モジュールは `th-rpi-ap` に乗り、無線でつなぐ |
| 上部モジュールの数 | **同時に複数繋げる**（2026-11-01 ユーザー決定。`H-M3`・`P-5` を改めた。旧: 同時に 1 台だけで、別の上部モジュールの接続が来たら新しい方に置き換える）。カメラモジュール・fk-system・ss-system が同時に繋がることを想定する。繋げる数の上限は詳細設計。**別の上部モジュールが繋がっても、繋がっている方は切らない**。**同じ上部モジュールが繋ぎ直したときは、古い接続を新しい方に置き換える**（古い方が昇降させていたらその場で止まる。2026-11-01 の提案。再起動で古い接続が残る場合のため） |
| 状態を読むだけの接続 | **昇降を命じず、状態（§3）だけを受け取る接続も受け付ける**（2026-11-01 ユーザー決定）。この接続からは昇降を命じられない。昇降部の画面を開いている端末の数（[Spec-ui.md](Spec-ui.md) §1.6）には数えない（2026-11-01 の提案） |
| 上部モジュールがあるとき | **昇降部の画面を開かなくても、すべての操作が上部モジュールからできる**（2026-10-06 ユーザー決定 `H-U8`）。昇降部の画面でできることは、すべて上部モジュールからもできるようにする。**例外: 測定機構の通信が切れたときの確認は、昇降部の画面でだけできる**（§5。2026-11-01 ユーザー決定。2026-11-14 にコネクタの確認から改めた） |
| 上部モジュールが昇降部を見つける方法 | 詳細設計に任せる（2026-10-06 ユーザー決定 `H-M2`）。AP 名と同じく、昇降部の居場所をコードに直書きしない |
| **口の名前と形** | **昇降部が上部モジュールに開く口（読む・動かす）の名前と形は本システムが書き、fk-system・ss-system が確かめる**（2026-11-05 ユーザー決定。fk-system の相談を受けた）。**fk-system・ss-system 用に別の口は作らず、カメラモジュールと同じ口で繋ぐ**（安全の判定の入口を 1 つに保つため）。**カメラモジュールが ss-system に開く口（ヨー・ピッチの操作・静止画の要求）の名前と形も本システムが書き、ss-system が確かめる**（2026-11-05 ユーザー決定。昇降部の口のあとに書く） |

## 2. 昇降部が受け付けるもの

| もの | 中身 |
| --- | --- |
| 昇降の命令 | 上昇・下降・停止と、その速度（mm/s。[Spec-ui.md](Spec-ui.md) §1） |
| **目標の高さへの移動** | **目標の高さまで動かし、着いたら止めて、着いたことを知らせる**（2026-11-01 ユーザー決定。§2.1） |
| 昇降の設定の変更 | 速度の下限・上限・初期値と、モータへの出力の上限（[Spec-ui.md](Spec-ui.md) §2・§2.1。2026-10-06 ユーザー決定 `H-U8`）・単体の操作でも天井で止めるか・天井の閾値（2026-11-06） |
| 天井の距離計を持っているか | **上部モジュールが自分で送る**（2026-10-06 ユーザー決定） |
| 天井までの距離 | 距離計を持つ上部モジュールが送る（[Spec-safety.md](Spec-safety.md) §1・2026-10-06 ユーザー決定）。**自分が昇降を命じていない間も送る**（ほかの上部モジュールの命令の判定に使うため。2026-11-01 の `H-X11` の決定の帰結） |

**昇降の命令（目標の高さへの移動を含む）は、押している間だけ続く操作として扱う。**命令が途切れたら（上部モジュールの故障・電池切れ・通信断）昇降は止まる
（旧版と同じ。止まるまでの時間は仮値で、実測で決める。`H-V8`）。

**下端まで下げる専用の命令は持たない。**下端まで下げたい上部モジュール（fk-system の移動の前・原点取りなど）は、**下降の命令を下端に着くまで送り続ける**（2026-11-05 ユーザー決定）。原点を取る前も使える（目標の高さへの移動は、原点を取る前は受け付けない。§2.1）。

### 2.1 目標の高さへの移動（2026-11-01 ユーザー決定）

**ユーザーが決めたのは「目標の高さへの上昇と、着いたことの報告」まで。下の表の細部は 2026-11-01 の提案で、覆ったら直す。**

| 項目 | 振る舞い |
| --- | --- |
| 向き | 上昇・下降とも（目標がいまの高さより下なら下降する） |
| 速度 | 昇降の命令と同じく、命令に載せる（mm/s） |
| 続け方 | **送り続けている間だけ続く**（上の段落と同じ）。着く前に送り手が落ちたら止まる。昇降部が勝手に動き続けない |
| 着いた | 目標の高さに着いたら止め、**着いたことを知らせる**。着いたとみなす幅は未定（`H-M6`） |
| 着く前に止まった | 安全の判定（[Spec-safety.md](Spec-safety.md) §2）・取って代わられた（§4）・命令の途切れ・停止の命令で止まったら、**着かなかったことと理由を知らせる** |
| 高さが読めない | 受け付けない（原点を取る前を含む。[Spec-safety.md](Spec-safety.md) §1.2）。理由を知らせる |
| 安全の判定 | 押している間だけ動く命令と同じに効く（下端・上端・天井・#4・#4b・#4d） |
| 高さの精度 | 高さはロープの巻き取りから数えるので、実際の位置とずれうる（[Spec-safety.md](Spec-safety.md) §1.2・`H-V12`）。**最後の位置合わせは、指示する側が映像・接触の検知で行う前提**にする |

**上昇してよいかは昇降部が決める**（2026-10-06 ユーザー決定。`H-M4`）。上部モジュールは**距離そのもの**を送り、止める判定を肩代わりしない。
天井の閾値を昇降部が持つので、上部モジュールを替えても天井の止め方が変わらない（閾値は昇降部の設定。2026-11-06。[Spec-ui.md](Spec-ui.md) §2.3）
（旧版の詳細設計では、カメラ部が「上昇してよいか」の判断を作って指令に載せていた）。

**天井の距離を使うかは、命令の出どころで決まる**（2026-10-06 ユーザー決定。`H-X10`。[Spec-safety.md](Spec-safety.md) §2 #4c）:

| 命令の出どころ | 天井の距離 |
| --- | --- |
| 上部モジュール（距離計を持つと送ってきたもの） | **使う**（[Spec-safety.md](Spec-safety.md) §2 #3〜#4） |
| 昇降部の画面（単体での操作） | **設定「単体の操作でも天井で止める」（[Spec-ui.md](Spec-ui.md) §2。既定は入）が入っていて、距離計を持つ上部モジュールと通信できているときは使う**（その値で判定する。距離計が読めないと知らせてきたら上昇しない）。**設定が切、または通信できない・値が古いときは使わない。**上昇を許し、人が見て守る（2026-11-06 ユーザー決定で `H-X10` を改めた。[Spec-safety.md](Spec-safety.md) §2 #4c） |
| 上部モジュール（距離計を持たないと送ってきたもの） | **使う。距離計を持つ上部モジュール（カメラモジュール）が送ってくる天井の距離で判定する。**距離計を持つ上部モジュールが繋がっていない・値が古いときは**上昇しない**（[Spec-safety.md](Spec-safety.md) §2 #4）。2026-11-01 ユーザー決定で `H-X11`（旧: 使わずに上昇を許す）を改めた。fk-system・ss-system が距離計を持たずに自動で上げても、天井で止まるように |
| 昇降部の物理ボタン（点検用） | **昇降部の画面と同じ**（同じ設定に従う。2026-11-06 ユーザー決定。2026-10-29 は「使わない」。[Spec-ui.md](Spec-ui.md) §0.3） |

下端・上端・連続駆動の上限は、命令がどこから来ても同じに効く。
距離計を持つ上部モジュールが 2 台以上繋がったときにどの値で判定するかは未定（`H-M5`。いまはカメラモジュールだけが持つ）。

## 3. 昇降部が配信するもの

**旧版の操作画面が昇降について出していたものを、すべて配信する。**上部モジュールがそれを自分の画面に出せるようにするため。
状態を読むだけの接続（§1）にも同じものを配信する。

| もの | 例 |
| --- | --- |
| 昇降の高さ | 読めないとき（高さの原点が決まる前を含む。[Spec-safety.md](Spec-safety.md) §1.2）は「読めない」と分かる形で |
| 上下端の状態 | 下端に着いている・上端に達した・上端が未設定 |
| いまの動き | 止まっている・上昇中・下降中、と速度（目標と、測った速さ） |
| 止めた理由 | [Spec-safety.md](Spec-safety.md) §2 #5 |
| いま操作している元 | 昇降部の画面・上部モジュール（**どの上部モジュールか**。2026-11-01）・**物理ボタン**・**アームの制御器**（§5。2026-11-01）のどれか（物理ボタンで操作中は遠隔から動かせないと分かるように。[Spec-ui.md](Spec-ui.md) §0.3） |
| 繋がっている上部モジュール | どれが繋がっているか・それぞれ天井の距離計を持つか（2026-11-01） |
| 目標の高さへの移動 | 移動中の目標の高さ・着いた・着かなかった（と理由）（§2.1） |
| 天井の扱い | 昇降部が受け取っている天井の距離（どの上部モジュールから来たか）と、それで上昇を止めているか。**いまの操作で天井を使っているか、使っていないならその理由（単体の操作で設定が切・単体の操作で通信なし）**（2026-11-06。[Spec-safety.md](Spec-safety.md) §2 #4c） |
| 測定機構 | 付いているとみなしているか（アームの制御器と通信できたか）・いまアームの制御器と通信できているか・確認待ちか（§5。2026-11-14 に改めた。ドラムの状態は外した）・**腕が格納位置にないか**（アームの制御器から受け取る。2026-11-02）。**分からないとき（アームの制御器と一度も通信できていない・確認で解いたあと・アームの制御器から届かないときを含む）は「分からない」と分かる形で**出し、「付いていない」「格納位置にある」と取り違えない（2026-11-05 ユーザー決定。fk-system の頼み。付いていないと読むと、fk-system は腕の条件を満たしたとみなして機体を動かすため）。**コネクタが無くなったので、昇降部は「付いていない」とは出せない**（2026-11-14。付いているとみなしているか、分からないかのどちらか） |
| 昇降の設定 | 速度の下限・上限・初期値と、モータへの出力の上限（[Spec-ui.md](Spec-ui.md) §2・§2.1）・**単体の操作でも天井で止めるか**・**天井の閾値**（2026-11-06） |

## 4. 複数の操作元

**上部モジュールと昇降部の画面（と、それを開いている複数の端末）から同時に命令が来たときは、最後の操作が勝つ**
（旧版 `P-3` の延長。止めたいときに止められない場面を作らないため。2026-10-06 ユーザー決定 `H-M1`）。
**上部モジュールが複数になっても同じ**（2026-11-01）。カメラモジュール・fk-system・ss-system のあいだでも最後の操作が勝ち、人が画面から押せばいつでも取って代われる。
**アームの制御器（§5）からの命令も同じ。**
**fk-system と ss-system がぶつからないよう気をつけるのは fk-system**（fk-system `FD-11`）。昇降部は上部モジュールどうしの順番を決めない。取って代わられたことは、配信の「いま操作している元」（§3）で分かる。

**取って代わられた側が指を離しても、いま動かしている側の昇降は止まらない**（2026-10-06 ユーザー決定 `P-9`）。止めたい人はもう一度押して自分の操作にし、離せば止まる。
**止まったあとは、新しく押し始めた操作でなければ動かない**（遅れて届いた古い操作で動き出さない）。

**例外: 昇降部の物理ボタン（点検用）は、押している間はこの規則より優先する**（2026-10-29 ユーザー決定。[Spec-ui.md](Spec-ui.md) §0.3）。押している間は遠隔の命令で取って代わられない。押せば遠隔の操作から取って代わる。離したあと、遠隔は押し直さなければ動かない。

## 5. 測定機構との取り決め（2026-11-01 ユーザー決定。2026-11-14 に改めた）

fk-system からの申し送り（fk-system [Spec-arm.md](../../../../fk-system/docs/plan/spec/Spec-arm.md)）。**いまの仮の構成（fk-system [arm.md](../../../../fk-system/docs/plan/arm.md)）による**ので、測定機構の構成が変われば見直す。

**2026-11-14 fk-system の決定で、腕を起こすドラムは昇降機の上部へ移ってアームの制御器が動かし、昇降部の基板のコネクタは無くなった**（fk-system [Spec-open.md](../../../../fk-system/docs/plan/spec/Spec-open.md) §1.2。hve のユーザーが申し送りを受けた）。
ドラムは昇降機と一緒に上下するので、**昇降機が動いても腕の角度は変わらない**。昇降部はドラムを動かさず、腕の角度も受け取らない。
測定機構が昇降部とやり取りするのは、**上部モジュールとして繋ぐ部分**（fk-system。§1〜§4 のとおり）と、腕の根元に置く**アームの制御器**との無線の通信だけである。

| 項目 | 振る舞い |
| --- | --- |
| ドラム | **昇降部は動かさない。アームの制御器が動かす**（2026-11-14 fk-system の決定。それまでは機体側に付き、昇降部が腕の角度を保つように動かしていた）。ドラムの制御・電源が切れてもその場で保つことは fk-system の側で満たす（fk-system [Spec-arm.md](../../../../fk-system/docs/plan/spec/Spec-arm.md)） |
| 付いているかの検知 | **アームの制御器と通信できたら、測定機構が付いているとみなす**（2026-11-14 ユーザー決定。コネクタが無くなったため）。**起動してから一度も通信できていなければ「分からない」と配信し（§3）、今までどおり単体で動かせる**（[Spec.md](Spec.md) §4 `HD-4`）。昇降部は「付いていない」とは判定できない |
| 付いているとみなしているとき | **アームの制御器と無線で通信する**（アームの制御器は無線と電池で、昇降機と一緒に上下する線は持たない。2026-11-02 fk-system の決定。`H-A13`）。**アームの制御器は、腕が格納位置にないかを昇降部へ知らせる**（2026-11-02 fk-system が承認。下の「測定中の表示」と「通信できない」に使う）。腕の角度は受け取らない（2026-11-14） |
| アームの制御器からの命令 | **測るときは、アームの制御器が主導して昇降機を動かす**（2026-11-02 fk-system の決定。`H-M7` の一部）。何をどこまでアームの制御器に任せるかは fk-system [Spec-arm.md](../../../../fk-system/docs/plan/spec/Spec-arm.md) §1。それ以外の昇降は、fk-system が上部モジュールとして直接命じる（§2）。**アームの制御器からの昇降の命令は、上部モジュールからの命令と同じに扱う**: 天井（カメラモジュールの値。§2）・上端・下端・連続駆動の上限・エンコーダが回らないときは、昇降部が命令を拒んで守る（[Spec-safety.md](Spec-safety.md) §2）。**最後の操作が勝つ**（§4）ので、人が画面や物理ボタンで押せば取って代わる。アームの制御器は、取って代わられたことを知って止まる（2026-11-02 fk-system が承認） |
| 腕の画面 | **アームの制御器も自分で画面を配信し、人がそこで腕を操作できる**（異常のときの対処用で、操作は人が責任を負う。2026-11-04 fk-system の決定）。**人の端末から、`th-rpi-ap` を通さずにも腕の画面につなげるようにする**（2026-11-04 ユーザー決定。fk-system の要望。アームの制御器は生きていて無線だけが切れたときや AP の不調のときにも、手で腕を戻せるように。形は `H-M7`） |
| **測定中の表示** | **fk-system（アームの制御器を含む）が昇降を動かしている間と、腕が格納位置にない間は、昇降部の画面とカメラモジュールの画面に出す**（[Spec-ui.md](Spec-ui.md) §1.6）。**人の操作は拒否しない**（2026-11-02 ユーザー決定。fk-system からの申し送り）。腕が出ているのに気づかず昇降機を動かして腕を当てるのを防ぎ、人の邪魔はしないため |
| **通信できない** | **腕が格納位置にない（または腕の状態が分からない）と最後に知った状態で、アームの制御器と通信できなくなったら、昇降機を動かさない。上昇も下降もしない。点検用の物理ボタンでも動かさない**（[Spec-safety.md](Spec-safety.md) §2 #4e。2026-11-14 ユーザー決定。2026-11-01 の「測定機構を検知しているのに通信できない」を、コネクタが無くなったので改めた）。**最後に格納位置にあると知っていたなら、止めない**（腕の状態は「分からない」と配信する。§3）。基本は、異常を解消して通信を戻してから動かす。**通信が戻れば、確認なしで動かせる。直せないときは、人が腕の安全を確かめ、下の確認で解く** |
| **確認**（2026-11-14 ユーザー決定。`H-U10` を改めた） | **上の「通信できない」で止めている間、昇降部の画面に確認ダイアログを出す。確かめるのは「測定機構を取り外した、または腕の安全を確かめたか」だけ。**答えたら昇降機を動かせる。そのあとは、次にアームの制御器と通信できるまで、起動してから一度も通信できていないときと同じに扱う（「分からない」と配信する。「付いていない」とは出さない）。**確認できるのは昇降部の画面だけ**（§1 の `H-U8` の例外。fk-system・ss-system・カメラモジュールの画面からは確認できない）。確認待ちであることを止めた理由として配信し（§3）、カメラモジュールの画面と fk-system にも「昇降部の画面で確認してください」と分かるようにする。**答えたあとの昇降は、人が腕を見ながら動かす**（昇降部は腕を見ていない。腕が出たまま下げれば天面に降り、上げれば天井に近づく）。それまでのコネクタの確認ダイアログ（抜き差しを確かめる。2026-11-01・2026-11-02）と、コネクタを抜いて下げる抜け道（2026-11-04）は無くした |
| **電源を入れ直したあと** | **最後に知った腕の状態は覚えていない**（覚えておくかは未定。`H-X15`）。アームの制御器と通信できるまでは「分からない」になり、上の「通信できない」では止めない（原点を取るまでは下降だけ。下の「原点取り」） |
| **原点取り**（2026-11-02） | 昇降部は電源を入れ直すと、一度下端に着くまで上昇しない（[Spec-safety.md](Spec-safety.md) §1.2）。測定中に電源が切れると、ドラムはその場で保つので、腕は起きたまま残り、そのまま下げると腕が天面に降りる。**fk-system は、腕が格納位置にないときは原点取りの下降をせず、腕を格納してから下げる**（昇降機を上げられず格納もできないときは人が判断する。fk-system の決定）。**昇降部は、高さが読めない間に腕が格納位置にないと知らされていたら、画面に警告を出す。下降は拒否しない**（2026-11-02 ユーザー決定。[Spec-ui.md](Spec-ui.md) §1.6） |
| 腕が出ている間の fk-system | fk-system の決まり（腕を起こす・格納するときの旋回の手順など）は fk-system [Spec-arm.md](../../../../fk-system/docs/plan/spec/Spec-arm.md) §1。**昇降部に効くのは次の 2 つ**（2026-11-02・2026-11-04 fk-system の決定）。**fk-system は、腕を起こしたまま旋回する前に毎回、昇降機で腕を十分に上げる**（お立会試験・自律測定とも。fk-system `FK-X7`）ので、**腕を起こしたまま昇降機を上げることがある**（腕を起こしたときの最も高い所が天井の余裕に効く。`H-V13`）。**昇降部が上昇を拒むなどで十分に上げられないと、fk-system は旋回せずに止まり、人が判断する** |
| 昇降機が引っかかったとき | 下降中に昇降機が引っかかると、ロープだけ繰り出されて高さの表示だけが下がる（[Spec-safety.md](Spec-safety.md) §1.2）。ドラムは昇降機と一緒に上下し、昇降部は動かさないので、高さの表示がずれても腕を起こす線には効かない（2026-11-14）。**引っかかりが外れて昇降機が落ちるとき、腕が出ていたらどう扱うかは未定**（`H-X13`） |
| 電源 | **ドラムのモータの電源をどこから取るかは fk-system で未定**（fk-system `FK-X3`）。「昇降機のモータと同じ電源系統にする」（2026-11-01 ユーザー決定）は、理由（片方だけ止まると腕を起こす線が張るか緩む）が無くなったので 2026-11-14 に取り下げた（[Spec-safety.md](Spec-safety.md) §4）。昇降部の電源から取ることになったら、電流が足りるかを確かめる（`H-V13`）。**アームの制御器は電池で、fk-system の非常停止を無線で受ける**（2026-11-02 fk-system の決定）。th-system の物理非常停止では止まらない（カメラモジュールと同じ） |

**昇降部とアームの制御器の間の通信の取り決めは、本システムが書き、fk-system が確かめる。アームの制御器のファーム（2026-11-14 からドラムの制御を含む）は fk-system が書く**（2026-11-01 ユーザー決定。2026-11-02 fk-system も承認）。
**「付いているかの検知」「通信できない」「確認」の形は、hve の見解として fk-system に返したもので、fk-system の側（fk-system `FK-X5`）はまだ決まっていない。**決まったら合わせ直す。
