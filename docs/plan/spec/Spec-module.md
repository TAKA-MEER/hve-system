# Spec-module — 昇降部と上部モジュールの取り決め

[Spec.md](Spec.md) §4 `HD-4` の詳細。**上部モジュールを替えても昇降部を作り直さない**ための、両者の間の約束。
通信の手段・形式・周期は書かない（詳細設計の役割）。

---

## 1. 方針（2026-10-06 ユーザー決定）

| 項目 | 振る舞い |
| --- | --- |
| 昇降部 | **単体で動かせる。**自分の操作画面を持ち、上部モジュールが無くても昇降できる |
| 上部モジュール | **ソフトウェアごと交換できる。**昇降部に**昇降を命じ**、昇降部から**状態を受け取る** |
| つなぎ方 | どちらも `th-rpi-ap` に乗り、無線でつなぐ |

## 2. 昇降部が受け付けるもの

| もの | 中身 |
| --- | --- |
| 昇降の命令 | 上昇・下降・停止と、その速度 |
| 天井までの距離 | 天井を測れる上部モジュールが送る（[Spec-safety.md](Spec-safety.md) §1・2026-10-06 ユーザー決定） |

**昇降の命令は、押している間だけ続く操作として扱う。**命令が途切れたら（上部モジュールの故障・電池切れ・通信断）昇降は止まる
（旧版と同じ。止まるまでの時間は仮値で、実測で決める。`H-V8`）。

**提案・確認待ち（`H-M4`）**: 天井について、上部モジュールは**距離そのもの**を送り、**上昇を止めるかは昇降部が決める**。
昇降部の止める判定（上下端・天井・連続駆動の上限）は命令がどこから来ても同じに効き、上部モジュールは止める判定を肩代わりしない。
（旧版の詳細設計では、カメラ部が「上昇してよいか」の判断を作って指令に載せていた。
この案では天井の閾値を昇降部が持ち、上部モジュールを替えても天井の止め方が変わらない。`H-X10` と一緒に決める）

## 3. 昇降部が配信するもの

**旧版の操作画面が昇降について出していたものを、すべて配信する。**上部モジュールがそれを自分の画面に出せるようにするため。

| もの | 例 |
| --- | --- |
| 昇降の高さ | 読めないときは「読めない」と分かる形で |
| 上下端の状態 | 下端に着いている・上端に達した・上端が未設定 |
| いまの動き | 止まっている・上昇中・下降中、と速度 |
| 止めた理由 | [Spec-safety.md](Spec-safety.md) §2 #5 |
| 天井の扱い | 昇降部が受け取っている天井の距離と、それで上昇を止めているか（`H-M4` 次第） |
| 昇降の速度の設定 | 下限・上限・初期値（[Spec-ui.md](Spec-ui.md) §2） |

## 4. 複数の操作元

**上部モジュールと昇降部の画面（と、それを開いている複数の端末）から同時に命令が来たときは、最後の操作が勝つ**
（旧版 `P-3` の延長。止めたいときに止められない場面を作らないため。**v2 での確認待ち** `H-M1`）。
