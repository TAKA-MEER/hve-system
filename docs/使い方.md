# カメラモジュール（UnitV2）の使い方（v2）

**実装を知らない人が、UnitV2 にカメラ部のアプリを入れ、動いているか確かめ、元に戻すまでの手順書。**
今日何を確かめるかはここに書かない（`docs/試験項目.md`）。動かし方が変わったら、同じコミットでここも直す。

対象は M5Stack UnitV2 に、Arduino UNO（ヨー・ピッチ・天井の距離計）を Grove の UART でつないだ**カメラモジュール**。
昇降部（ESP32）は別の手順。機器の構成は [DetailedDesign-hardware.md](plan/detailed/DetailedDesign-hardware.md) §2。
旧版（ラズパイ 4）の手順は、この節より下の「旧版 v1」。

## V2-1. 用意するもの

- PC（Linux）に `ssh`・`sshpass`・`tar`。このリポジトリを `camera/deploy/` が見える所に置く
- UnitV2 の電源を入れ、PC から届く状態にする。届き方は次の 2 つ
  - **Wi-Fi（`th-rpi-ap`）**: UnitV2 はもともと `th-rpi-ap` に繋がる設定が入っている。IP は `th-rpi-ap` が DHCP で配る（例 `192.168.5.129`）。わからないときは USB 経由で `ip addr show wlan0` を見る
  - **USB の有線**: UnitV2 を PC に USB で繋ぐと **`10.254.239.1`** で入れる。**配備後も変わらない**（保守用の回線）
- ユーザーは `m5stack`、パスワードは `12345678`。root の作業は `sudo`（同じパスワード）

## V2-2. 配備する（アプリを入れて自動起動にする）

リポジトリ直下から、**UnitV2 の IP を渡して** 1 回実行する。何度流しても同じ結果になる（原本のバックアップは初回の 1 回だけ取る）。

```bash
camera/deploy/install.sh 192.168.5.129    # Wi-Fi の場合（IP は実際の値に）
camera/deploy/install.sh                  # USB の有線（10.254.239.1）の場合
```

これで次のことが起きる（**電源を入れるだけでアプリが立ち上がる**ようになる）。

| 変えるもの | 内容 |
| --- | --- |
| `/home/m5stack/hve/camera/` | アプリ（`hve_camera`・`hve_video`・画面・設定）を置く |
| `/etc/init.d/S86hve` | **新規**。起動時に `hve_camera`（:80）と `hve_video`（:8080）を root で起動する |
| `/etc/init.d/S85runpayload` | 組み込みの認識サービス（:80 とシリアルを占有する）を自動起動から外す（`off.S85runpayload` に改名） |
| `/etc/init.d/S90wifi-conf` | UnitV2 自前の AP（`M5UV2_xxxx`・hostapd）を起動しない（`th-rpi-ap` の帯域を食うため） |
| `/etc/avahi/avahi-daemon.conf` | `allow-interfaces` に `wlan0` を足す（`hve-lift.local` を引くため） |
| `/etc/init.d/S23oadfsko` | 起動で `grace.ko` を読ませない（これが固まって Wi-Fi が繋がらないことがあった） |

**変える前の原本は `/home/m5stack/hve_backup/` に残る**（root だけが読める）。差分そのものは `camera/deploy/os/*.diff`。
Wi-Fi の設定（`wlan0`・`wpa_supplicant`）と USB の有線の設定（`S95ip-conf`）には触らない。
配備のあと、再起動しなくてもアプリは立ち上がっている。**確実に確かめたいときは UnitV2 の電源を入れ直す**（V2-3 を再起動後にもやる）。

## V2-3. 動いているか確かめる

**PC から**（`<IP>` は UnitV2 の IP）

1. ブラウザで `http://<IP>/` を開く。**カメラモジュールの画面**が出る（昇降・ヨー・ピッチ・ズーム・設定）。昇降部に繋がっていれば画面の昇降部の欄が接続中になる
2. `http://<IP>:8080/snapshot` を開く。1280×720 の静止画が出る。`http://<IP>:8080/stream` は映像（約 8 fps）

**UnitV2 の中で**（`sshpass -p 12345678 ssh m5stack@<IP>` で入る。**`S86hve` の操作は必ず `sudo` をつける**）

```bash
echo 12345678 | sudo -S /etc/init.d/S86hve status   # hve_camera・hve_video が running
ps | grep -E "hostapd|check_thermal|haveged"        # hostapd は出ない／check_thermal.py と haveged は出る
cat /proc/modules | grep grace                       # 何も出ない（読んでいない）
avahi-resolve-host-name -4 hve-lift.local            # 昇降部の IP が返る
echo 12345678 | sudo -S tail -n 20 /home/m5stack/hve_log/hve_camera.log
```

- ログは `/home/m5stack/hve_log/`（256 KB × 3 世代で回る。**フラッシュなので `/tmp` には溜まらない**）。時計は NTP につながらず 1970 年のことがある
- 昇降部に繋がると、ログに `昇降部 ws://… に繋がった` が出る。昇降部の画面（`http://<昇降部の IP>/`）の接続の欄にも出る

## V2-4. 止める・起動し直す

```bash
echo 12345678 | sudo -S /etc/init.d/S86hve stop      # 止める
echo 12345678 | sudo -S /etc/init.d/S86hve start     # 起動する
echo 12345678 | sudo -S /etc/init.d/S86hve restart   # 起動し直す
```

- **組み込みのサービスを `S85runpayload stop` で止めない**（温度監視まで殺される）
- アプリが死んでも自動では立ち上げ直さない。`restart` するか、電源を入れ直す
- UnitV2 のメモリは 116 MB。**`ffmpeg` を使わない**（メモリを使い果たして温度監視まで殺される）

## V2-5. 元に戻す（ロールバック）

```bash
camera/deploy/uninstall.sh 192.168.5.129            # 上の変更をすべて原本に戻す（アプリは残す）
camera/deploy/uninstall.sh 192.168.5.129 --purge    # アプリとログも消す
```

OS のファイルは退避した原本のまま（`cp -p`）に戻り、`S86hve` が消え、`S85runpayload` が元の名前に戻る。
**そのあと UnitV2 の電源を入れ直す**と、組み込みのサービスと自前の AP が元どおり立ち上がる（それまでは止まったまま）。
原本は `/home/m5stack/hve_backup/` に残るので、PC に繋がらなくなっても、UnitV2 の中で
`echo 12345678 | sudo -S sh /home/m5stack/hve_backup/restore_os.sh` で戻せる。

## V2-6. 困ったとき

| 症状 | 見ること |
| --- | --- |
| 電源を入れて 3 分待っても `<IP>` に届かない | USB で PC に繋ぎ（`10.254.239.1`）、`ip addr show wlan0` で IP を見る。`wlan0` が無い・繋がらないときは電源を入れ直す。それでも繋がらなければ V2-5 で戻す |
| 画面が開かない | `S86hve status`。止まっていればログ（V2-3）を見て `restart` |
| `hve_camera` が `Arduino との UART を開けなかった` | UNO の配線と、組み込みのサービスが止まっているか（`ps` に `server_core.py` が無い）を確かめる |
| 画面の昇降部の欄が「未接続」 | 昇降部の電源・同じ Wi-Fi か。`avahi-resolve-host-name -4 hve-lift.local` が引けなければ、`params.toml` の `lift_host` に IP を書く |
| 映像だけ出ない | `ps` に `hve_video` と `v4l2-ctl` があるか。無ければログ `hve_video.log` |

# （旧版 v1）カメラ部の使い方 — ラズパイ版

> **これは旧版（v1）の手順書。** v2 のカメラモジュールは UnitV2 で、上の「v2」の節を見る。以下の `## 1.`〜`## 8.` は、ラズパイ 4 でカメラ部を作った旧版のまま残してある。

**実装を知らない人が、カメラ部のラズパイを準備して起動するまでの手順書。**
今日何を確かめるかはここに書かない（`docs/試験項目.md`）。動かし方が変わったら、同じコミットでここも直す。

対象はラズパイ 4（Raspberry Pi OS Lite 64-bit・Trixie）に、ピッチ（SG90）・ヨー（28BYJ-48 + ULN2003）・
天井の距離計（SRF02）・Web カメラをつないだ**カメラ部**。昇降部（ESP32）は別の手順。

配線の根拠は [DetailedDesign-hardware.md](plan/archive/v1/detailed/DetailedDesign-hardware.md)（§2 ピン・§3 電源）。

---

## 1. OS を入れる

1. Raspberry Pi Imager で **Raspberry Pi OS Lite (64-bit)**（Debian **Trixie** 版）を SD カードへ書く。
   書く前の設定で、ホスト名・ユーザ名・パスワード・SSH の有効化・**インターネットに出られる無線 LAN** を入れておく。
2. 起動して ssh で入り、更新する。

```bash
sudo apt update && sudo apt full-upgrade -y && sudo reboot
```

**この章と 3 章は、インターネットのある網で行う。**`th-rpi-ap` にはインターネットへの経路が無い（6 章）。

---

## 2. カーネルの設定（PWM と I2C）

SG90 はカーネルのハードウェア PWM（GPIO18）、SRF02 は I2C バス 1（GPIO2・3）を使う。

```bash
sudo nano /boot/firmware/config.txt
```

末尾に次の 2 行を足す（`raspi-config` に PWM の項目は無い）。

```
dtparam=i2c_arm=on
dtoverlay=pwm,pin=18,func=2
```

`/dev/i2c-1` を作るカーネルモジュールも読み込ませる（Trixie では自動では入らない）。

```bash
echo i2c-dev | sudo tee -a /etc/modules
```

保存して `sudo reboot`。戻ってきたら確かめる。

```bash
ls /sys/class/pwm      # pwmchip0 が出る
ls /dev/i2c-1          # /dev/i2c-1 が出る
```

`pwmchip0` が出なければ `config.txt` の綴りを、`/dev/i2c-1` が出なければ `/etc/modules` の `i2c-dev` を見直す。

### 2.1 権限

動かすユーザ（以下 `pi`。違うなら読み替える）を次のグループへ入れ、**ログインし直す**。

```bash
sudo usermod -aG gpio,i2c,video pi
```

### 2.2 `/sys/class/pwm` を書けるか確かめる

```bash
cd /sys/class/pwm/pwmchip0
echo 0 > export            # 「Permission denied」なら 2.1 のグループを見る
ls                          # pwm0 が増えている
echo 0 > unexport
```

**Trixie では udev 規則を足さなくてよい**（2026-09-29 実機で確認）。OS 同梱の規則（`99-com.rules`）が、`export` の少し後に
`pwm0` の権限を `gpio` グループへ付ける。アプリはその間 `period` の書き込みを最大 2 秒待つので、再起動後の初回でも起動できる。
手で `echo 0 > export` した直後に `ls` の中身へ書くと、`Permission denied` になることがあるが、少し待てば書ける。
待っても `Permission denied` のままなら、2.1 のグループ（`gpio`）を確かめる。

## 3. コードと仮想環境

```bash
sudo apt install -y git python3-venv python3-lgpio python3-opencv python3-numpy i2c-tools
git clone <リポジトリの URL> ~/hve-system
cd ~/hve-system
python3 -m venv --system-site-packages .venv
.venv/bin/pip install -r camera/requirements.txt
.venv/bin/pip install -e camera
```

- **`--system-site-packages` を必ず付ける。**`lgpio` と OpenCV は OS 同梱のものを使う（pip に Python 3.13 向けの `lgpio` が無い）。
- `pip install -e camera` で `python -m hve_camera` と `python -m hve_video` が動く。`PYTHONPATH` は要らない。

確かめる。

```bash
cd ~/hve-system
.venv/bin/python -c "import lgpio, smbus2, cv2; print('ok')"     # ok と出る
.venv/bin/python -m hve_video --help                              # 使い方が出る
```

`No module named lgpio` は、仮想環境を `--system-site-packages` 無しで作った。`rm -rf .venv` して作り直す。

## 4. 配線

| 部品 | 端子 | つなぐ先 |
| --- | --- | --- |
| SG90（ピッチ） | 信号（オレンジ） | GPIO18（ハードウェア PWM） |
| SG90 | 5 V（赤）・GND（茶） | **モータ用の 5 V** |
| ULN2003（ヨー） | IN1・IN2・IN3・IN4 | GPIO23・GPIO24・GPIO25・GPIO16 |
| ULN2003 | 5 V・GND | **モータ用の 5 V** |
| SRF02（天井） | SDA・SCL | GPIO2・GPIO3 を **I2C レベル変換器（I2C-LVL01）経由**で |
| SRF02 | 5 V・GND | ラズパイの 5 V ピン（レベル変換器の 5 V 側）・GND |
| Web カメラ | USB | ラズパイの USB |

- **SG90 と 28BYJ-48 の 5 V をラズパイの 5 V ピンから取らない。**動き出しの電流でラズパイが再起動する。
  モバイルバッテリの 2 つ目の出力をモータ専用にするか、バッテリからシールド基板へ直接入れる。**GND はラズパイと共通にする。**
- **SRF02 は 5 V 動作の I2C。**GPIO2・3（3.3 V）へ直結せず、シールド基板の I2C-LVL01 を通す。
- SRF02 のアドレスは出荷時の `0x70`。ピンには仮のものがある。変えたら [DetailedDesign-hardware.md](plan/archive/v1/detailed/DetailedDesign-hardware.md) §2.2 と合わせる。

SRF02 が見えるか確かめる。

```bash
/usr/sbin/i2cdetect -y 1        # 表の 70 の位置に「70」と出る（Trixie では PATH に無いのでフルパス）
```

出なければ、電源・レベル変換器・SDA と SCL の入れ違いを見る。

## 5. 起動する

### 5.1 偽物で先に確かめる

配線を疑う前に、アプリ自体が動くかを偽物で確かめる。

```bash
cd ~/hve-system
.venv/bin/python -m hve_camera --fake --port 18000
```

別の機器のブラウザで `http://<ラズパイの IP>:18000/` を開く。画面に **`fake`** と出る。Ctrl+C で止める。

### 5.2 実物

```bash
.venv/bin/python -m hve_camera --port 18000     # 80 番を使うときは systemd で（7 章）
.venv/bin/python -m hve_video --port 8080       # 別の端末で。映像
```

- `http://<ラズパイの IP>:18000/` が画面、`http://<ラズパイの IP>:8080/` が映像。
- ラズパイ以外で `--fake` 無しに起動すると、案内を出して終了コード 2 で止まる。
- 起動直後にピッチのサーボが**正面（水平）へ動く**。ヨーは回らない。
- `ラズパイのハードウェアを開けなかった` と出たら、直前のログにある理由を見る
  （権限は 2.1、PWM は 2.2、I2C は 4 章）。

## 6. 無線 LAN（`th-rpi-ap`）へ移す

インターネットのある網で 1〜5 章を済ませてから、AP へつなぐ。AP の名前は将来変わりうるので**コードや設定に直書きしない**。

```bash
sudo nmcli device wifi connect "<AP の名前>" --ask
ip addr show wlan0
```

つないだあと、5 章の URL を新しい IP に読み替える。昇降部（ESP32）へは `camera/config/params.toml` の `lift_ws_url` で行く。

---

## 7. 起動時に自動で走らせる（systemd）

ユニットは `camera/systemd/` にある。**そのままでは動かない。**各ファイルの先頭の「準備時に直す所」を環境に合わせて直す。

| 直す所 | 既定（仮） |
| --- | --- |
| `User=` `Group=` | `pi` |
| `WorkingDirectory=` | `/home/pi/hve-system` |
| `ExecStart=` の `python` | `/home/pi/hve-system/.venv/bin/python` |

`hve-camera.service` は **:80 で待つ**ので `AmbientCapabilities=CAP_NET_BIND_SERVICE` を付けてある。**root にしない。**

```bash
sudo cp ~/hve-system/camera/systemd/hve-camera.service ~/hve-system/camera/systemd/hve-video.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now hve-camera hve-video
systemctl status hve-camera hve-video        # 両方 active (running)
journalctl -u hve-camera -f                  # ログ（Ctrl+C で抜ける）
```

`http://<ラズパイの IP>/`（80 番）が画面、`:8080` が映像。`sudo reboot` して自動で上がることも確かめる。

止めるとき・自動起動をやめるとき。

```bash
sudo systemctl stop hve-camera hve-video
sudo systemctl disable hve-camera hve-video
```

## 8. 困ったとき

| 症状 | 見るところ |
| --- | --- |
| `Permission denied: '/sys/class/pwm/...'` | 2.1 のグループ。再起動後の初回だけなら 2 秒待つ（2.2） |
| `gpiochip0 が開けない` | `gpio` グループに入っているか（入れたあとログインし直したか） |
| `i2cdetect` に 70 が出ない | 4 章の電源・レベル変換器・SDA と SCL |
| `No module named lgpio` | 3 章。仮想環境を `--system-site-packages` 付きで作り直す |
| ポート 80 が開けない | 手で動かすときは `--port 18000`。systemd なら `AmbientCapabilities` の行が残っているか |
| 画面は出るが昇降部が `lost` | 昇降部の電源と `lift_ws_url`、無線につながっているか |
